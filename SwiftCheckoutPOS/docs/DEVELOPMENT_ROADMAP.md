## Sequencing and completion rules

Fix Immediately means prerequisites for a trustworthy executable and safe data path, **not permission to apply unreviewed production changes**. Before Production tasks are release gates. Future Enhancements are optional and justified by measured/operator need.

Resolve owner questions for the affected workflow **before selecting its calculation or stock/refund semantics**. Technical defects such as malformed input, stale overwrites, unsafe paths and missing atomicity do not need invented policies to fix. PR-Q38 requires actual historical evidence; never “backfill” missing historical costs from current product prices or zero.

Every implementation task must identify touched use cases, original audit evidence/label, approved rules, schema impact, regression checks and retained-record/rollback implications. For existing databases: reviewed generated SQL, actual target/schema inventory and verified pre-change recovery **first**; never startup Migrate/EnsureCreated. No task authorizes rebuilding the application, distributed infrastructure or deleting history.

Where tasks overlap, implement one cohesive correction and cross-link it rather than maintaining duplicate mechanisms. Establish the test harness early in implementation so later tasks have evidence; BP-10 lists release-suite completion rather than postponing all tests.
